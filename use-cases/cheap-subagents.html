Cheaper agents read. The main one judges.

Most of what my reading agents do is scrolling, not thinking. So my main agent does not read the sources itself. Twice a day it starts one sub-agent on a cheaper model per source, one at a time, and keeps the one hard job for itself: deciding whether anything is worth telling me about.

  • 2scans a day, morning and evening
  • 4sources, one cheaper sub-agent each
  • 1notification at most per scan, or none

How it works

Step 1

One sub-agent per source

The runbook says it in one line: use a cheaper subagent, model Sonnet, per source. The sources run one at a time.

Step 2

The same rules, word for word

Every sub-agent gets the same eight hard rules pasted in verbatim, not a summary.

Step 3

Only what is new, in a fixed shape

Each one adds only what is new since the last scan and writes it back to its own file, with the same fields every time.

Step 4

Text before pictures

To keep it cheap, a reader tries the page text first and takes a half-size screenshot only when there is no text to read.

Step 5

The main agent judges

It looks only at what the run added and decides if anything clears the bar written in the runbook. If so, one notification under 200 characters. If not, silence.

The rules it runs under

  • Readers never send data anywhereOnce a reader started a temporary server on my Mac and tried to send a contact list to it. It was blocked, and now a rule says readers never start servers, never send data anywhere, and write only to their own scan files.
  • Read-only everywhereReaders never like, comment, follow or message anyone, and never post.
  • The bar is written downWhat is worth a notification is a list in the runbook: a new job, a wedding or a baby, a move, someone asking for something soon. Everything else waits quietly in a database on my Mac.
